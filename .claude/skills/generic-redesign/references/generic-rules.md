# 범용화 규칙 (Generalization Rules)

고객사 제출용 제안서를 **어느 고객사에나 보낼 수 있는 범용 교육 프로그램 소개서**로 바꿀 때의 기준.
2026-10-30(1차 10건)·2026-11-09(2차 10건) 작업에서 사용자가 승인한 규칙이다.

## 1. 지우거나 일반화할 것

| 원본 | 범용본 | 예시 |
|---|---|---|
| 고객사명 (표지·제목·본문·엔딩·노트·파일명) | 삭제하거나 대상 직무·업종으로 일반화 | "코미코 주재원 역량 강화" → "글로벌 주재원 역량 강화 과정" |
| 고객사 대상 표현 | 일반 대상 | "삼성전자 협력사 임직원" → "제조 기업 품질·공정 실무자" |
| 고객사 고유 산업 맥락 | 업종 공통 표현 (예시로만 남김) | "반도체 제조 품질 특성" → "제조 품질 특성", "웨이퍼맵" → "맵 패턴" |
| 비교 사례에 나온 타사명 | 업종 descriptor | "삼성전자 해외법인 교육" → "글로벌 전자기업 해외법인 교육" |
| 일정·장소·차수 날짜 | "협의" | "2026. 04. 14 / 상생아카데미" → 삭제, 일정·인원 "협의" |
| 인원 | "협의" (원본이 운영 원칙으로 둔 상한은 유지 가능: "차수별 30명 이내") | |
| 고객사 담당자·내부 연락망 | 고객사 → "고객사 담당자" (역할만) | |
| 디자이너 목업 브랜딩 (예: MIRI COMPANY, "2080 하반기") | 삭제 | |
| 감사 문구의 고객사 언급 | 삭제 | "삼성전자의 든든한 파트너로서…" → 삭제 |
| "CONFIDENTIAL", 제안 날짜, PROPOSED BY 블록 | 삭제 | |

## 2. 그대로 둘 것

- **강사 학력·경력·출강 이력**: 사실 기록이므로 고객사명(삼성 등) 포함 그대로 유지. 오탈자만 수정 (예: "프렌차이즈" → "프랜차이즈").
- 과정 내용·모듈·시간 배분·학습 방법: 원본 그대로 (문장은 다듬되 사실·수치 변경 금지).
- 원본이 둔 운영 정책 문구 (예: "확정 일정 1주일 이내 변경 시 교육비 100% 발생").

## 3. 예산 페이지

- **총액 → 단가 + 산정 방식**: `kit.budget_unit()` 사용. 시간당 강사료 hero, 항목별 단가 표, `단가 × 시간 × 차수 = 교육비` 수식 띠.
- 총액은 note 한 줄에만 예시로: `※ 1차수 6H 기준 1,800,000원(VAT 별도) · 운영 시간 · 인원 · 차수에 따라 조정 가능`.
- 원본 산식·합계가 **서로 안 맞으면 계산이 맞는 쪽(단가×시간)으로** 쓰고 보고서에 flag. (예: "6시간×300,000 = 2,100,000" → 1,800,000)
- "VAT 별도"로 표시된 합계가 실제로는 VAT 포함이면 별도 금액 기준으로 쓰고 flag.
- 원본에 예산이 없으면 예산 페이지를 **만들지 않는다** (가격을 지어내지 않음).

## 4. 엔딩·연락처

- 표준 연락처: `CONTACTS` — 저장소에 커밋하지 않는다(공개 저장소일 수 있음). `generic-redesign/contacts.local.txt`(한 줄에 한 명, gitignore 대상) 또는 환경변수 `GR_CONTACTS`(`이름 직함 · 전화 · 메일|…`)에서 읽는다. 둘 다 없으면 엔딩에 `담당자 · 연락처 · 이메일` 자리표시가 들어가므로, **사용자에게 엔딩 연락처를 물어** `GR_CONTACTS`로 넣고 다시 빌드한다.
- 원본 연락처가 표준 연락처와 다르거나 자료끼리 번호가 불일치하면 표준으로 통일하고 flag.
- 엔딩 accent = 과정명(고객사명 없이).

## 5. 내용을 지어내지 않는다

- 원본에 없는 세부(모듈 상세, 가격, 일정)를 만들어야 할 때는 **원본의 요약 정보만으로 구성**하고, 해당 슬라이드에 `※ 원본에 세부 페이지가 없어 과정 개요 기준으로 구성한 안입니다` 주석 + 보고서 flag.
- 원본끼리 수치가 충돌하면 (예: 강의 30/실습 70 vs 이론 40/실습 60) 하나를 고르고 flag.

## 6. 파일·저장

- 납품: `<원본 파일명에서 고객사명 뺀 이름>_범용.pptx` → 기본 폴더 `~/OneDrive/바탕 화면/김주영 업무폴더/범용과정_리디자인/` (사용자가 다른 폴더를 말하면 그쪽).
- 원본 파일은 읽기만 — 이동·수정 금지. `extract_source.py`는 작업 폴더에 사본을 만든다.
- 프로젝트 폴더: `output/<주제>_generic` (ASCII, 주제명만).

## 7. 최종 보고 (덱마다)

납품 경로 + 장수, 그리고 **원본 데이터 이상 flag 목록**: 산식 불일치, VAT 표기 오류, 지어낸 부분, 수치 충돌, 연락처 불일치, 예산 미포함 사유.
